# 희망나누미론 백엔드

대출 상담 신청과 담당자 1:1 실시간 채팅을 지원하는 정식 백엔드 서버입니다. 이전에 만든 웹 프로토타입(브라우저 안에서만 동작하던 버전)을 대체하는, 실제로 배포해서 여러 사람이 동시에 접속할 수 있는 버전이에요.

## 업데이트: 푸시 알림 지원 추가
앱이 완전히 꺼져 있어도 담당자에게 알림이 가도록 Firebase Cloud Messaging(FCM) 연동을 추가했어요.
- `.env`에 `FIREBASE_SERVICE_ACCOUNT_JSON`을 설정하지 않으면 이 기능은 자동으로 비활성화되고, 기존처럼 앱을 열어둔 상태에서의 실시간 알림(소켓)만 동작해요. 서버가 멈추지는 않아요.
- 설정 방법은 `hope-loan-app-shell` 프로젝트의 README 5번 항목("푸시 알림 설정하기")에 자세히 정리해 뒀어요.
- 새 API: `POST /api/notifications/register-token` — 담당자 로그인 후 앱이 발급받은 기기 토큰을 서버에 등록.

## 이번 버전에서 새로 생긴 것
- **정식 서버**: Node.js(Express) + Socket.io로 만든 백엔드. 브라우저를 꺼도 데이터가 서버에 안전하게 남아 있어요.
- **실시간 채팅**: Socket.io를 이용해 고객과 담당자가 메시지를 주고받으면 새로고침 없이 즉시 반영돼요.
- **계정 보안 강화**: 비밀번호는 평문이 아니라 bcrypt로 해시되어 저장되고, 로그인은 JWT 토큰으로 인증돼요. 로그인 시도 횟수도 제한(15분에 20회)되어 있어요.
- **권한 검사는 서버에서**: 총관리자/서브관리자 권한 체크를 브라우저가 아니라 서버 쪽에서 다시 한번 검사해서, 화면을 조작해도 남의 상담을 보거나 계정을 바꿀 수 없어요.

## 아직 안 된 것 (다음 단계)
- **앱이 꺼져 있을 때 오는 푸시 알림**: 지금은 앱을 열어 두면 실시간으로 알림이 오지만, 완전히 꺼진 상태에서 오는 휴대폰 푸시는 별도 작업이 필요해요.
- **앱스토어에 올리는 네이티브 앱**: 지금은 웹사이트 형태예요. 앱스토어/플레이스토어에 올리려면 React Native 등으로 별도 개발이 필요해요.
- 준비되시면 이어서 말씀해 주세요.

## 1. 로컬에서 실행하기

```bash
cd hope-loan-backend
npm install
cp .env.example .env
```

`.env` 파일을 열어 `JWT_SECRET` 값을 아무도 예측할 수 없는 긴 문자열로 바꿔주세요. 아래 명령으로 무작위 값을 만들 수 있어요.

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

서버 실행:

```bash
npm start
```

브라우저에서 `http://localhost:3000` 접속하면 됩니다.

## 3. 어떻게 동작하나요

- 고객이 이름/연락처/필요 금액을 남기면 서버가 총관리자+서브관리자 5명(총 6명) 중 다음 차례인 담당자에게 자동으로 배정해요. (`src/routes/consultationRoutes.js`의 `getNextStaff`)
- 배정 직후 담당자에게 실시간 알림(화면 상단 토스트)이 가고, 목록이 자동으로 갱신돼요.
- 채팅은 Socket.io로 오가고, 모든 메시지는 서버의 SQLite 데이터베이스(`data.sqlite`)에 저장돼요.
- 총관리자는 모든 상담을 보고 수정/삭제할 수 있고, 서브관리자는 본인에게 배정된 상담만 볼 수 있어요. 이 권한은 서버 쪽 코드(`authRequired`, `requireRole`)에서 검사하기 때문에 클라이언트 화면을 조작해도 우회할 수 없어요.

## 4. 실제 서비스로 배포하기

Render, Railway, Fly.io 같은 서비스에 Node.js 프로젝트로 그대로 올릴 수 있어요. 배포 시 체크할 것:

1. 환경변수 `JWT_SECRET`을 반드시 설정하세요 (커밋하지 마세요).
2. `data.sqlite` 파일이 저장될 디스크가 재배포/재시작 후에도 유지되는지 확인하세요 (예: Render의 Persistent Disk). 그렇지 않으면 배포할 때마다 데이터가 초기화돼요.
3. 동시 접속자가 많아지고 데이터가 커지면 SQLite 대신 PostgreSQL 같은 정식 데이터베이스로 옮기는 걸 권해요. (`src/db.js`의 쿼리 부분만 바꾸면 돼요.)
4. HTTPS는 대부분의 호스팅에서 기본 제공돼요. 자체 서버(VPS)에 올리는 경우 Let's Encrypt 등으로 HTTPS를 꼭 적용하세요.
5. 실제 고객의 이름·연락처·대출 정보를 다루는 서비스이니, 정식 오픈 전에 개인정보보호법 및 대출 중개 관련 법적 요건을 확인하세요.
